## 힙 (Heap)

힙은 **부모가 자식보다 항상 크거나(최대힙) 작은(최소힙)** 규칙을 가진 완전 이진트리다. "최댓값/최솟값을 반복해서 꺼낸다"는 요구에 최적화된 구조다.

```text
최소힙
        1
      /   \
     3     2
    / \   /
   5   4 6
```

BST와 다르다. BST는 왼쪽 < 부모 < 오른쪽이라는 **좌우 순서**를 지키지만, 힙은 부모-자식 **상하 순서**만 지킨다. 그래서 힙에서는 정렬된 순서를 얻으려면 순회가 아니라 계속 꺼내야 한다.

### 배열로 구현

완전 이진트리라는 성질 덕분에 포인터 없이 배열 인덱스만으로 부모-자식 관계를 계산할 수 있다.

```text
인덱스:     0   1   2   3   4   5
값:         1   3   2   5   4   6

부모(i)     = Math.floor((i - 1) / 2)
왼쪽 자식(i) = 2i + 1
오른쪽 자식(i) = 2i + 2
```

### 삽입 (heapify up)

배열 맨 끝에 추가한 뒤, 부모와 비교하며 규칙에 맞을 때까지 위로 올린다.

```javascript
class MinHeap {
  #values = [];

  insert(value) {
    this.#values.push(value);
    let i = this.#values.length - 1;

    while (i > 0) {
      const parent = Math.floor((i - 1) / 2);
      if (this.#values[parent] <= this.#values[i]) break;
      [this.#values[parent], this.#values[i]] = [this.#values[i], this.#values[parent]];
      i = parent;
    }
  }
```

### 삭제 (heapify down)

루트(최솟값)를 꺼내고, 맨 끝 값을 루트로 옮긴 뒤 자식과 비교하며 아래로 내린다.

```javascript
  extractMin() {
    const min = this.#values[0];
    const last = this.#values.pop();
    if (this.#values.length === 0) return min;

    this.#values[0] = last;
    let i = 0;

    while (true) {
      const left = 2 * i + 1;
      const right = 2 * i + 2;
      let smallest = i;

      if (left < this.#values.length && this.#values[left] < this.#values[smallest]) smallest = left;
      if (right < this.#values.length && this.#values[right] < this.#values[smallest]) smallest = right;
      if (smallest === i) break;

      [this.#values[i], this.#values[smallest]] = [this.#values[smallest], this.#values[i]];
      i = smallest;
    }
    return min;
  }
}
```

### 시간 복잡도

| 연산 | 복잡도 | 이유 |
|------|--------|------|
| 삽입 | O(log n) | 트리 높이만큼 위로 이동 |
| 최댓값/최솟값 추출 | O(log n) | 트리 높이만큼 아래로 이동 |
| 최댓값/최솟값 조회 | O(1) | 항상 루트(인덱스 0) |
| 임의 값 탐색 | O(n) | 정렬 규칙이 없어 전체 확인 필요 |

"최대/최소만 반복 추출"이 필요하면 힙이다. 정렬 전체가 필요한 게 아니라면 굳이 O(n log n) 정렬을 쓸 필요가 없다.

### 우선순위 큐 (Priority Queue)

우선순위 큐는 "먼저 넣은 순서"가 아니라 "우선순위가 높은 순서"로 꺼내는 추상 자료형이고, 힙은 이를 구현하는 가장 효율적인 방법이다. JS에는 내장 힙/우선순위 큐가 없어서 위 코드처럼 직접 구현해야 한다.

### FE에서의 힙 — React Scheduler

React의 내부 스케줄러(`scheduler` 패키지)는 실제로 **최소힙**으로 작업 큐를 관리한다. 여러 작업이 동시에 대기 중일 때, 만료 시각(expirationTime)이 가장 이른 — 즉 우선순위가 가장 높은 — 작업을 매번 O(log n)에 꺼내기 위해서다. `setState`가 여러 번 겹쳐도 급한 업데이트(사용자 입력)가 덜 급한 업데이트(백그라운드 렌더링)보다 먼저 처리되는 게, 이 힙 기반 우선순위 큐 덕분이다.

## 그래프 (Graph)

그래프는 **정점(vertex)과 정점을 잇는 간선(edge)으로** 이루어진 자료구조다. 트리는 그래프의 특수한 형태다 — 사이클이 없고, 모든 정점이 루트에서 하나의 경로로만 연결된 그래프.

```text
방향 그래프              무방향 그래프
A → B                   A — B
↓   ↓                   |   |
C → D                   C — D
```

- **방향 그래프**: 간선에 방향이 있다 (팔로우 관계, 웹페이지 링크)
- **무방향 그래프**: 간선에 방향이 없다 (친구 관계, 도로망)
- **가중치 그래프**: 간선마다 비용(거리, 시간 등)이 있다

### 표현 방법

**인접 행렬 (Adjacency Matrix)**: 정점 × 정점 크기의 2차원 배열. `matrix[i][j] = 1`이면 i → j 간선이 있다는 뜻이다.

```text
     A  B  C  D
A  [ 0, 1, 1, 0 ]
B  [ 0, 0, 0, 1 ]
C  [ 0, 0, 0, 1 ]
D  [ 0, 0, 0, 0 ]
```

**인접 리스트 (Adjacency List)**: 각 정점이 자신과 연결된 정점 목록만 가진다.

```text
A → [B, C]
B → [D]
C → [D]
D → []
```

| | 인접 행렬 | 인접 리스트 |
|---|---|---|
| 공간 복잡도 | O(V²) | O(V + E) |
| 간선 존재 확인 | O(1) | O(V) (최악) |
| 모든 인접 정점 순회 | O(V) | O(간선 수) |
| 적합한 경우 | 간선이 많은 밀집 그래프 | 간선이 적은 희소 그래프 (대부분의 실전 케이스) |

실전에서는 정점 수에 비해 간선이 적은 경우가 많아 **인접 리스트**를 기본으로 쓴다.

```javascript
const graph = new Map([
  ['A', ['B', 'C']],
  ['B', ['D']],
  ['C', ['D']],
  ['D', []],
]);
```

### 그래프 탐색: DFS / BFS

트리 순회와 코드 구조는 같지만, 그래프는 **사이클이 있을 수 있어 같은 정점을 두 번 방문하면 무한 루프**에 빠진다. `visited` 집합으로 방문 여부를 반드시 체크해야 한다.

```javascript
const dfs = (graph, start, visited = new Set()) => {
  if (visited.has(start)) return [];
  visited.add(start);

  const result = [start];
  for (const neighbor of graph.get(start)) {
    result.push(...dfs(graph, neighbor, visited));
  }
  return result;
};

const bfs = (graph, start) => {
  const visited = new Set([start]);
  const queue = [start];
  const result = [];

  while (queue.length > 0) {
    const node = queue.shift(); // 실전에서는 인덱스 포인터로 O(1) 처리 권장
    result.push(node);

    for (const neighbor of graph.get(node)) {
      if (visited.has(neighbor)) continue;
      visited.add(neighbor);
      queue.push(neighbor);
    }
  }
  return result;
};
```

DFS는 "일단 갈 수 있는 데까지 깊이 가본다"(경로 탐색, 사이클 판별), BFS는 "가까운 곳부터 한 겹씩 넓힌다"(최단 거리)에 적합하다.

> 다익스트라(최단 경로)·위상 정렬은 여기서는 개념만 짚는다. 그래프 자체의 표현·순회가 핵심이고, 이 둘은 FE 코딩테스트에는 잘 나오지 않는다.

### FE에서의 그래프

**모듈 의존성 그래프**: webpack·Vite 같은 번들러는 `import`로 연결된 파일 관계를 그래프로 구성한다. 정점은 모듈, 간선은 `import` 관계다. 순환 참조(circular dependency) 경고는 이 그래프에서 **사이클을 탐지**한 결과다.

```text
a.js → b.js → c.js → a.js   ← 순환 참조 (사이클)
```

**라우트 구조**: Next.js의 파일 기반 라우팅도 폴더 구조를 따라가는 트리(그래프의 특수 형태)이고, 페이지 간 링크(`<Link>`)까지 포함하면 사이트 전체가 방향 그래프가 된다.

**상태 의존성**: 여러 atom/selector가 서로를 구독하는 상태 관리 라이브러리(Recoil, Jotai)는 내부적으로 의존성 그래프를 만들어, 값이 바뀌면 그래프를 따라 영향받는 노드만 다시 계산한다.

## 정리

- 힙은 부모-자식 상하 순서만 지키는 완전 이진트리. 배열 인덱스만으로 부모/자식 위치 계산 가능
- 삽입·삭제는 O(log n), 최댓값/최솟값 조회는 O(1) — "최대/최소 반복 추출"에 최적
- 우선순위 큐는 힙으로 구현하는 게 표준. JS엔 내장이 없어 직접 구현해야 한다
- React Scheduler는 작업 우선순위 관리에 최소힙을 실제로 사용한다
- 그래프는 정점 + 간선. 표현은 인접 행렬(밀집)보다 인접 리스트(희소)가 실전에서 더 많이 쓰인다
- 그래프 탐색은 트리와 코드 구조가 같지만 사이클 때문에 `visited` 체크가 필수
- 번들러의 모듈 의존성, 순환 참조 탐지, 상태 관리 라이브러리의 의존성 추적이 모두 그래프 구조다
